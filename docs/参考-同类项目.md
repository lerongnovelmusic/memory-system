# 同类项目参考：claude-mem

> 只做功能介绍，没有安装。

## 它是什么

[claude-mem](https://github.com/thedotmack/claude-mem) 是一个给编码 agent 用的**持久记忆插件**（Apache-2.0，TypeScript）。
解决的问题很直白：每次新会话，agent 都从零开始——重读同样的文件、重问同样的问题、重新踩已经修过的坑。

官网文档：[docs.claude-mem.ai](https://docs.claude-mem.ai/)

## 它怎么工作

和我们的系统几乎是同一个循环，只是对象从"陪伴对话"换成了"编码操作"：

1. **捕获**：靠 agent 的生命周期钩子，把每次工具调用（读了什么、改了什么、跑了什么）交给一个本地 worker。
2. **观察**：另一个 agent 在旁边做笔记，把这些活动压成一条条短观察，会话结束时再写一份总结。
3. **注入**：下一次会话开始时，先给一份很短的索引，需要细节时再按 ID 去取。

存储是 SQLite（全文检索）+ Chroma（向量检索），数据在本机 `~/.claude-mem`。

## 值得注意的几个设计

**三层检索，按需付费。** `search` 只返回约 50–100 token 的索引行，`timeline` 给时间上下文，`get_observations` 才取完整记录（500–1000 token）。先过滤、再取详情——这个"渐进披露"的思路比一次把所有相关记忆塞进上下文省得多。

**隐私开关。** 用 `<private>` 标签包起来的内容永远不落库。

**多 agent 支持。** Claude Code、Codex、Cursor、OpenCode 等十余种，也支持装进 **DeepSeek Harness**（`npx claude-mem install --ide dsh`）。

**可选云同步。** 默认全本地，同步是 opt-in。

## 和我们这套的区别

| | claude-mem | 我们这套 |
|---|---|---|
| 对象 | 编码会话 | 陪伴对话 |
| 记忆单位 | 观察 + 会话总结 | 事件 + 事实 + 线索 |
| 会忘记吗 | 不会。只增不删，靠检索裁剪 | 会。容量驱动淘汰 + 时间衰减 |
| 会被推翻吗 | 不处理"旧说法失效" | 双时态：旧记录标 superseded，永不作为事实注入 |
| 巩固时机 | 会话结束（边干边记） | 每晚一次批处理 + 可补跑 |
| 人格/契约 | 无此概念 | 独立存储，不参与权重竞争、不可淘汰 |
| 评测 | 无内置回归评测 | 探针 + 口径固定的 dry/full 体检 |

一句话概括差异：**claude-mem 是"别忘"，我们这套是"该忘的忘、该记的记、被推翻的别乱说"**。
前者适合写代码（信息越全越好），后者适合长期相处（记太多反而不像人）。

## 如果要借鉴

1. **渐进披露**：我们现在的回忆一次给 3–5 条全文，可以改成"先给索引，模型自己决定要不要展开"。
2. **`<private>` 标签**：比"整条记忆 pin 住"更细粒度，实现成本很低。
3. **时间线视图**：`timeline` 那个接口比单纯的相似度排序更接近人回忆的顺序。
