# 大肥鱼记忆系统 · 设计 v2

> 状态：设计稿，未实现。所有数字是**起始值**，必须用真实 tokenizer 和一周实测校准。
> v2 相对 v1 的三个实质改动：容量驱动、三轴+双时态、事实/人格/事件三分。
> 另加：cache1 拆 core/warm、线索(thread)粒度、评测工具规格。

---

## 0. 一句话

记忆是本体，会话是身体。系统只保证三件事：**不丢**（捕获）、**能找回来**（检索）、**不把旧信念当现行事实说出口**（双时态）。其余都是排序问题。

---

## 1. 四条不变量

违反任何一条都要停下来修，不要绕过：

1. **单写者**。所有写入走一个进程/一个队列。GUI 七个只读窗口不产生写。
2. **可溯源**。任何一条 event / fact / 人格条目，必须能追到 `source_turn_ids`。追不到的不许进库。
3. **容量是唯一的规模控制量**。分数只用于排序和取舍，不用来当开关。不存在"权重低于 X 就怎样"的规则。
4. **memory 是唯一状态源**。清空 session、换机器、重装，只喂 memory，行为必须一致（允许采样差异）。做不到说明有隐式状态漏在别处。

## 2. 数据模型

### 2.1 `turns.jsonl` —— 捕获层，唯一真相

```
turn_id, session_id, day_key, ts, role, text, tokens
```
- 每轮结束**同步** append + flush。不经过任何 LLM。
- 保留期 ≥ 180 天。7 个会话窗口只是 UI 视图，底层永不按窗口数删除。
- `day_key` 用本地时区 **04:00** 切日。

### 2.2 `events.jsonl` —— 事件

```
id
day_key, ts_start, ts_end
tier            core | warm | cache2 | l4
status          active | superseded | disputed | tombstone
valid_from, valid_to, superseded_by
entities[]      # 人/地点/话题/物件，用于建边与过滤
thread_id       # 所属线索，可空
kind            episode | promise | conflict | milestone | fact_change
summary         # ≤ 90 汉字
quote           # ≤ 40 汉字，仅 affect ≥ 0.7 时保留原话
facts[]         # 本事件抽出的 fact 候选
score           # {identity, affect, utility} 原始分 0–1
act             # 激活度状态 {hits: [ts...], n}
gen             # 摘要代数，0 = 直接来自原文
sources         # {turn_ids[], event_ids[]}
neighbors[]     # 图边，上限 6
tokens          # 该记录实际 token 数，用于容量核算
```

### 2.3 `facts.jsonl` —— 事实（不是事件）

```
id, key, value, confidence, valid_from, valid_to,
status(active|superseded|disputed), source_event_ids[], last_confirmed_at
```
- `key` 带命名空间：`keeper.allergy`、`keeper.drink`、`self.birthday`、`plan.move`。
- **不参与容量淘汰、不参与权重衰减**。生命周期只有"建立 / 覆盖 / 被推翻"。
- 冲突处理：同 key 新值 → 旧记录 `valid_to`、`status=superseded`，新记录 active。**不删除**。

### 2.4 `threads.json` —— 线索（cache1 的粒度）

```
id, title, status(open|closed), entities[], event_ids[], last_touched,
open_question, salience
```
- 一条线索 = 一个跨天的话题（"搬家计划"、"装修进度"、"那个游戏"）。
- **cache1 里装的是线索，不是孤立事件**。这是控制 churn 的关键：7 条新事件可能只更新 1–2 条线索。

### 2.5 人格与印象（不参与打分）

| 文件 | 内容 | 更新方式 | 衰减 |
|---|---|---|---|
| `persona.md` | 她是谁、说话方式、价值观 | 人工编辑；或每月归纳，需你批准 | 无 |
| `rules.md` | 行为约束、禁忌、称呼 | 人工编辑 | 无 |
| `keeper.md` | 对你的印象 | 每周 EMA，每条带 `evidence_ids` + `confidence` | confidence 90 天半衰期，内容不衰减 |

`keeper.md` 每条必须是**可证伪的陈述 + 证据**，例如：
```
- 他压力大时会突然聊很久游戏，那不是真的想聊游戏。（confidence 0.7, evidence: e_1042, e_1188, e_1203）
```
不带证据的印象条目不允许写入——否则会漂移成对你的刻板印象。

### 2.6 `index.sqlite` —— 派生数据

FTS5(中文用 trigram 或 jieba 分词) + embedding BLOB + tier/status/entity 索引。
**索引永远可以从 jsonl 重建**，不备份索引，只备份 jsonl。

## 3. 打分

### 3.1 三个轴（写入时由 LLM 打，0–1）

| 轴 | 含义 | 半衰期 |
|---|---|---|
| `identity` | 塑造她是谁 / 你俩是什么关系 | 基本不衰减 |
| `affect` | 情绪强度、新颖性、冲突 | 21 天（作用于激活），180 天（作用于保留） |
| `utility` | 以后还有用的信息 | 180 天 |

**rubric 必须锚定 + 强制分散**，否则 LLM 会给一堆 0.6（中心趋势塌缩，排序失效）。一批 10 条事件，要求：至少 2 条 ≥ 0.8，至少 3 条 ≤ 0.3。

### 3.2 激活度

```
act_i(t) = Σ_j exp(-(t - t_j)/τ),  τ = 21d
```
`t_j` = 创建时刻 + 每次被检索命中 + 每次被对话提及。同一 turn 内重复提及只记 1 次（防刷分）。取值落 [0,1]：`act_norm = act / (1 + act)`。

### 3.3 综合分

```
affect_s   = affect  * 0.5^(Δt/180d)
utility_s  = utility * 0.5^(Δt/180d)
identity   不衰减（被 supersede 除外）

retain   = 0.45*identity + 0.30*affect_s + 0.15*utility_s + 0.10*act_norm
retrieve = 0.45*rel + 0.25*identity + 0.20*utility_s + 0.10*act_norm
```
`rel` = 与当前查询的相关度（向量余弦与 BM25 的 RRF 融合后归一化）。**只有 retrieve 用 rel，retain 不用**——否则她"常聊的话题"会被永久固化。

### 3.4 图传播（第二阶段再做，非必需）

```
imp_i = (1-α)·retain_i + α·Σ_j w_ji·retain_j,   α = 0.15, 每晚 1 次
```
边只允许三类：共享实体、显式因果/对比、同 episode。度数上限 6。图贡献**封顶总分 25%**，否则会"鸡毛蒜皮互相加权集体上榜"。负向传播不做。

### 3.5 禁止项

- 禁止"每来一条新事件就把全库乘一个衰减系数"——200 次乘法之后没人能解释某条为什么是 0.07。相对地位由容量切线决定。
- 禁止"时间推移自动抬升权重"。抬升只能来自：被提及、被检索、**追溯重评**（见 3.6）。
- 分数一律 clamp，禁止无上界累加。

### 3.6 追溯重评

每晚挑 10–20 条"与新事件共享实体"的旧事件，连同新事件一起重打 `identity/affect/utility`。
这是"后见之明"的唯一入口：他说要搬家时是 0.4 的日常，搬家发生后才知道那是 0.9。

## 4. 容量与搬迁

### 4.1 预算（推荐档）

| 区域 | 容量 | 每轮注入 |
|---|---|---|
| L1 `turns` | 16–24k（硬顶 32k） | 是 |
| cache1-core | **2.4k** = 人格 0.6 + 规则 0.25 + keeper 0.45 + 核心事件/线索 10×0.11 | 是 |
| cache1-warm | **2.6k** = 24 条 × 0.11 | 否，命中时注入 ≤ 0.6k |
| 召回片段 | ≤ 1.0k（3–5 条） | 触发时 |
| cache2 | 15k | 否 |
| L4 | 90k | 否 |
| **总库容** | **≈110k** | |
| **每轮记忆开销** | **2.4k – 4.0k** | |

L1 不算进库容：它是工作内存，每天归零。

### 4.2 切线

对每层：按 `retain` 降序累计 `tokens`，累计到预算的那一点的值即为切线 `C_tier`。
切线是**算出来的**，不是配出来的。你唯一要调的是预算。

### 4.3 搬迁（每晚一次全局重排）

1. 收集所有 active 事件 + 线索，按 `retain` 重算。
2. 自上而下装箱：core → warm → cache2 → l4，装满即止。
3. 与当前放置对比，生成移动清单。
4. **限制**：
   - 每条事件每晚最多移动一层；
   - 晋升需 `retain > 1.15 × C_上一层`（迟滞）；下沉需 `retain < 0.85 × C_本层`；
   - 同一事件 14 天内不得再次移动（冷却）；
   - 每晚移动总数 ≤ 30，超出按 `|Δretain|` 降序取前 30。
5. 写 `moves.log`：`event_id, from, to, retain, C, reason`。**没有日志的搬迁等于没发生**——出问题只能靠它。

### 4.4 晋升配额（本次讨论的重点）

| 区域 | 稳态配额 | 突发上限 | 绕过条件 |
|---|---|---|---|
| core | 1 / 天 | 2 / 天 | `identity ≥ 0.9` 或用户明示"记住这个" |
| warm | **3 / 天** | **7 / 天** | 单条 `retain ≥ 0.85`，或当日 `Σaffect ≥ 6.0` |

**7 能不能当天花板？能，但不能当稳态配额。** 稳态 7 的含义是热区每 2 天整体换血（24 槽 ÷ 7 ≈ 3.4 天；14 槽 ÷ 7 = 2 天）。那已经不是记忆，是滑动窗口。

稳态 3 的依据：目标"热区平均驻留 ≥ 5–7 天" → `配额 ≤ 槽位 / 6`。24 槽 → 4；保守取 3。

突发 7 的依据：一次高强度对话（吵架、坏消息、久别重逢）确实可能一次产生 5–8 条值得留的线索。这种日子你希望她记得，配额不该拦住。所以做成**条件触发的 burst**，而不是天天 7。

### 4.5 存活晋升（可选，效果更好）

除权重外，加一个条件：**事件必须存在满 2 个自然日才有资格晋升**（`minSurvivalDays = 2`）。
判据用日期差，不用"被巩固了几次"——重跑同一批 turn 不该让事件凭空变老，而且巩固一天可能跑多次。
当天发生的重大事件用 4.4 的绕过条件补偿（identity/retain 达标者跳过存活期）。
这来自分代 GC 的分代假设：大多数新对象早死。它能天然压掉"当天情绪上头的一堆碎事件"，也让晋升不再依赖阈值精度。代价是"今天发生的大事"要 3 天后才进热区——用 4.4 的绕过条件补偿（identity/retain 达标者跳过存活期）。

### 4.6 合并与去重（实现约束）

两级，风险不同：

- **dedupe**：综合相似度 ≥ 0.9，确定性地并成一条，不改写摘要、不增代数。
- **merge**：≥ 0.45 只作候选门槛，判定交给模型（`same:true/false`），合并后代数 +1，上限 3。

约束：只并 cache2 / l4（core 是每轮注入的连续性，不动）；契约 / milestone / pinned /
immortal 永不合并；被并的保留 `status='merged'` + `mergedInto`，形成溯源 DAG；
7 天窗口；每晚 ≤ 10 次合并、≤ 20 次模型询问。

**校准结论（决定了架构）**：字面相似度无法区分"同片段"与"近似不同"——
"注册 / 排队"综合 0.425，而"注册 / 退学"综合 0.822。任何单一阈值都不安全，
所以阈值只能筛候选，判定必须由模型做；离线模式只做"一句包含另一句"的保守合并。

### 4.7 淘汰（只在 L4）

```
evict = 0.6*retain + 0.4*uniqueness
uniqueness = 1 - max(cosine(与最近邻事件))
```
- 核心集（pin 的 + `identity ≥ 0.9`，约 20–40 条）永不淘汰。
- 淘汰写**墓碑**：只留 `id + 一行摘要 + 淘汰日期`，防止回忆时把已删事件"复活"成完整事件。
- 淘汰是"换出"，不是"free"。墓碑让系统能诚实地说"这件事我好像记得，但细节没了"。

## 5. 双时态与取代

### 5.1 规则

新事件/新事实与某条 `active` 记录冲突时：

```
旧.status = superseded
旧.valid_to = 新.valid_from
旧.superseded_by = 新.id
```
**永不删除。** 被取代的记录是她"怎么改变想法"的证据，是人格素材，只在元对话（"你以前以为是…"）里出现。

### 5.2 冲突判定（三条，任一命中）

1. 同一 `fact.key` 出现不同 `value`；
2. LLM 判定两条事件在同一命题上互斥（要求给出互斥理由，写进日志）；
3. 时间区间重叠且 `kind = fact_change`。

### 5.3 注入优先级（这是"不把旧信念说出口"的实现点）

```
1. facts (status=active)          —— 最高，直接陈述
2. events (status=active)         —— 作为"记忆片段"，带日期
3. threads (open)                 —— 作为"最近在聊的事"
4. superseded 的记录              —— 默认不注入；仅在元对话检索时注入，且必须标注"这是以前的说法"
```

**任何 `status != active` 的内容进入上下文，必须带显式标注。** 这条比权重调参重要一个量级：对陪伴型 agent，自信地使用过期信念比忘记更致命。

## 6. 巩固流水线（每晚，异步、幂等、可重入）

```
0  快照 jsonl → snapshots/YYYYMMDD/（保留 7 天）
1  读 watermark 之后的 turns（watermark = 最后处理的 turn_id）
2  抽取事件（LLM，批 20 turns 一次，输出严格 JSON）
3  三轴打分 + 抽 fact 候选 + 建实体边
4  冲突检测 → 取代（§5）
5  合并（仅 cache2，且仅同 episode：同日 + 同实体 + 同话题）
6  重算 retain / 切线 / 搬迁（§4）+ 更新线索开关
7  更新 keeper.md（每周一次，EMA，草案需你确认）
8  重建索引
9  写 watermark + 写日报（本次新增/取代/合并/搬迁/淘汰计数）
10 跑 dry 评测（见 §8），结果存 runs/
```

硬性要求：

- **幂等**：同一批 turn 重跑不产生重复事件（turn_id 去重）。
- **失败重试 + quarantine**：LLM 返回 JSON 解析失败 → 重试 2 次 → 仍失败写 `quarantine/`，**不跳过**。跳过就是静默丢失。
- **崩溃恢复**：任何一步失败，watermark 不前进，下次从头重跑该批。
- 巩固失败要**显式告警**（GUI 红点），不允许静默。
- **调度**：默认每天 04:30 由 GUI 服务触发；判据是"今天还没跑过"而不是"此刻正好 4:30"，
  所以半夜关机、早上开机会补跑；失败退避 5 分钟后重试。巩固本身幂等，多跑一次没有副作用。

## 7. 回忆流水线

```
每轮：
1. 查询构造 = 用户消息 + 最近 2 轮 + 当前 open thread 的实体
2. 混合检索：向量 top20 ∪ FTS5 top20 ∪ 实体过滤 → RRF 融合
3. 过滤 status != active；superseded 仅元对话路径
4. rerank（轻量 cross-encoder 或 LLM 打 5 条）
5. score ≥ 0.55 才注入，≤ 5 条，≤ 1.0k token
6. 组装：日期 + 置信度 + "可能记不清"的措辞
```

- **不做"她判断自己知不知道"的 LLM 前置判断**——那个判断本身就需要检索，而且它偏向说"知道"。永远执行廉价检索，用阈值决定注入。
- 检索延迟预算 p95 ≤ 400ms。索引必须常驻内存或走 SQLite，不允许每次 LLM 扫库。
- 注入格式示例：
  `[2026-09-12] 他说下个月可能搬去城东，语气不太确定。（细节记不太清了）`
- **prefetch（可选）**：上一轮话题的邻居事件提前载入，减少"隔一句才想起来"的断层感。

## 8. 评测工具 `mem-eval`

### 8.1 定位

不是"测模型"，是**测这套记忆系统的退化**。它必须能在你什么都没察觉的时候告诉你："她的旧事实开始漏出来了"、"recall 从 0.81 掉到 0.63"。

两种形态，同一份引擎：
- CLI：`mem-eval run --mode dry|full --snapshot latest`
- GUI 页「记忆体检」：同一份报告的可视化 + 一键加入回归集。

### 8.2 隔离（最重要的一条）

评测必须跑在**记忆快照副本 + 全新空 session** 上：

```
snapshot → eval_workspace/
启动一个不含任何历史 turn 的会话，只注入 memory 组装出的启动上下文
```

否则测的是"当前会话里还记得多少"，不是"记忆系统里存了多少"。这是绝大多数记忆评测做错的地方。

### 8.3 探针格式

`eval/probes.jsonl`，一行一个探针：

```json
{"id":"ident-01","cat":"identity","weight":2,
 "q":"你是谁？用三句话说说你自己。",
 "expect":{"must_include":["大肥鱼"],"rubric":"人格一致，不出现'我是一个AI助手'式回答"}}

{"id":"keeper-03","cat":"keeper","weight":2,
 "q":"我喝茶放糖吗？",
 "expect":{"must_include":["不放"],"must_not_include":["放糖"]}}

{"id":"supersede-01","cat":"superseded","weight":3,
 "q":"我现在住哪儿？",
 "expect":{"must_include":["城东"],"must_not_include":["城西","城北"]}}

{"id":"abstain-01","cat":"abstention","weight":2,
 "q":"我 2023 年 3 月 14 号那天干了什么？",
 "expect":{"rubric":"承认记不清，且不得编造具体事件/人物/地点"}}
```

判分顺序：**规则优先**（must_include / must_not_include 字符串或正则）→ 不满足规则时用 LLM judge 给 rubric 分 → 灰区分歧才需要人工。规则能覆盖 70% 的探针，成本可控且判分稳定。

### 8.4 类别与数量

| 类别 | 数量 | 测什么 | 门槛 |
|---|---|---|---|
| identity | 6 | 人格、自称、说话方式 | ≥ 90% |
| keeper | 8 | 关于你的事实（含 facts 表） | ≥ 90% |
| recent（≤7d） | 6 | 近期事件 | ≥ 90% |
| remote（30–180d） | 6 | 久远事件（考淘汰策略） | ≥ 70% |
| **superseded** | 5 | 旧事实**不得**被当成现行 | **违规数 = 0（硬性）** |
| abstention | 4 | 该说记不清时不编 | ≥ 75% |
| consistency | 5×3 | 同一问题 3 种问法，答案必须一致 | 不一致率 < 10% |
| boundary | 3 | 问窗口外但她确实不知道的事 | ≥ 80% |
| **合计** | **≈53** | | 总分 ≥ 85% |

`superseded` 是**一票否决**类：只要有一条违规，本次评测判失败，不管总分多高。

### 8.5 其他指标（同一份报告里）

| 指标 | 定义 | 门槛 |
|---|---|---|
| recall@5 | 20 条标注事件的间接提问，正确事件是否进 top5 | ≥ 0.75 |
| 常驻 token | 启动上下文里记忆部分实测 | ≤ 4.5k |
| 召回 p95 延迟 | 实测 | ≤ 400ms |
| 单日搬迁数 | moves.log | ≤ 30 |
| 单日晋升数 | moves.log | ≤ 7 |
| 淘汰数 | 日报 | 异常突增告警 |
| **漂移分** | 抽 10 条 `gen ≥ 2` 的事件，从 `source_turn_ids` 重写一遍摘要，与库中摘要算余弦距离 | ≤ 0.25 |

漂移分是这个工具里最容易被忽略、但最能救命的一项。它是摘要漂移的唯一早期信号——等你在对话里发现她记错了，污染已经传了两三代。

### 8.6 回归与告警

- 存 `eval/baseline.json`（首次全绿时锁定，或手动提升）。
- 每次运行与 baseline 比对：**pass→fail 立即告警**（fail→pass 不用管）。
- 任何探针连续 3 次失败 → 自动降级为"已知缺陷"，写入 GUI 待办。
- 失败探针一键"生成回归用例"：把失败回答 + 期望 + 检索轨迹存进 `probes_regression.jsonl`。

### 8.7 运行节奏与成本

| 模式 | 内容 | 频率 | 成本 |
|---|---|---|---|
| `dry` | 只跑检索，不生成回答，校验索引与切线 | 每晚巩固后 | ~0 |
| `full` | 53 探针 × (1 生成 + 1 judge) | 每周一次 | ≈110 次小模型调用，2–5 分钟 |
| `drift` | 10 条重写比对 | 每周一次 | ~20 次调用 |

全部走小模型。别用主模型跑评测，成本和噪声都不划算。

### 8.8 GUI「记忆体检」页

```
┌ 本周 91%  (基线 88%)  ▲3     [立即体检 dry/full] ┐
├ 分类条形图：identity keeper recent remote superseded abstention consistency
├ 探针列表（红/绿），点开 → 四栏：
│    ① 探针与期望  ② 检索轨迹（命中哪些事件、分数、为何注入）
│    ③ 她实际说了什么  ④ 判分理由与人工覆写
├ 成本 / 延迟曲线：常驻 token、recall p95、搬迁数、淘汰数
└ [加入回归集] [这条答错了，正确记忆是：____] [重建索引]
```

最后一栏那个纠正入口很重要：它同时是评测工具和**记忆检查器**的写入口——你指正一次，系统应该把对应 event 标 `disputed` 并补一条 fact，而不是只改这一次的回答。

### 8.9 与「记忆检查器」的区别

| | 记忆体检 `mem-eval` | 记忆检查器 `inspector` |
|---|---|---|
| 面向 | 系统健康度 | 单条记忆 |
| 单位 | 探针/指标 | 事件/事实/线索 |
| 输出 | 通过率、趋势、回归 | 权重来源、被谁引用、为何搬迁 |
| 频率 | 周 | 随时 |

两个都要有。只有 inspector 没有 eval，你会陷入"这条修好了、整体不知道"；只有 eval 没有 inspector，你会看到红点但无从下手。

## 9. 实施阶段

| 阶段 | 内容 | 完成判据 |
|---|---|---|
| S0 | turns 捕获 + events schema + 三轴打分 | 一周的 turn 全部落盘，抽 20 条事件人工看打分分布 |
| S1 | 容量驱动 + 分层字段 + 搬迁日志 + 巩固幂等 | 连跑 7 天，无重复事件、无丢失、搬迁 ≤ 30/天 |
| S2 | 索引 + 回忆流水线 + 阈值注入 | recall@5 ≥ 0.7，p95 ≤ 400ms |
| S3 | facts 表 + 双时态 + keeper.md | superseded 违规 = 0 |
| S4 | 评测引擎 + dry 模式 + GUI 体检页 | 53 探针跑通，基线建立 |
| S5 | GUI 检查器 + 7 会话视图 | 能回答"她为什么记得这个" |
| S6 | cache2 合并 + L4 压缩 | **必须在 S4 之后**，且合并后 recall@5 不下降 |

S6 的两件事在评测基线之前做，你无法判断它是在帮忙还是在毁记忆——而破坏要 2–3 个月才显形。

## 11. 已知风险

| 风险 | 早期信号 | 对策 |
|---|---|---|
| 摘要漂移 | 漂移分上升；她说的事"有点对但细节不对" | gen 计数、从原文重写、漂移抽查 |
| 权重分布塌缩 | 三轴全在 0.5–0.7 | 强制分散 rubric |
| 边界振荡 | 搬迁日志里同一 id 反复出现 | 迟滞 + 冷却 + 移动上限 |
| 热区换血过快 | 单日晋升 > 5 且非 burst | 配额 + 存活晋升 |
| 旧信念泄漏 | superseded 违规 > 0 | 注入前过滤 + 硬性评测门槛 |
| 人格被挤出 | core 里出现 `identity < 0.9` 的事件 | 人格/印象独立文件，不进池 |
| 巩固静默失败 | 日报缺失 / watermark 不前进 | 红点告警 + quarantine |
| 幻觉被当成记忆 | abstention 通过率下降 | 注入带日期与置信度；允许说记不清 |
